# Assistant API (Vercel serverless)

The live chat on the [case-study page](https://meetbabariya.github.io/work/emotor-virtual-sensor/) calls this function. It is the same hand-written agent loop as `src/assistant.py`, ported to dependency-free JavaScript. The tools read precomputed data, so the function needs no pandas or PyTorch and cold-starts in about a second.

```
POST /api/ask   {"question": "Which cycles are hot restarts?"}
→ {"answer": "...", "tool_calls": [{"name": "find_hot_restarts", "input": {...}}], "seconds": 6.2, "model": "..."}
```

## Data

`data/` is generated by `python -m src.export_api_data web-api/data` from the trained virtual sensor:

| file | content |
|---|---|
| `cycles.json` | exact per-cycle summaries (same output as the Python tools) |
| `overheating.json` | overheating windows for every component × source × integer threshold 40–160 °C |
| `hot_restarts.json` | magnet-minus-coolant start difference per cycle |
| `what_if.json` | what-if grid for the 9 test + validation cycles (coolant −20…+20 °C × load 0.7…1.3) |
| `model_card.json` | accuracy and limitations |

Inputs between precomputed values are snapped, and the tool tells the model it did, so the answer can say so.

## Guards (public endpoint on a free-tier key)

- CORS and an origin check: only the portfolio origins (`ALLOWED_ORIGINS`) may call it.
- Questions are capped at 400 characters. At most 6 tool rounds per question, with a 25 s timeout per model call.
- Rate limits: 6 questions per IP per 10 minutes and 150 per instance per day (in memory, so best effort).
- The key lives only in Vercel environment variables and never reaches the browser.

## Environment variables

| name | purpose |
|---|---|
| `GEMINI_API_KEY` | free Google AI Studio key (required) |
| `GEMINI_MODEL` | defaults to `gemini-3.1-flash-lite` |
| `ALLOWED_ORIGINS` | comma-separated, default `https://meetbabariya.github.io,http://localhost:4322` |
| `EVAL_TOKEN` | optional; lets `python -m src.eval_assistant --endpoint …` skip the rate limit |

## Run and test locally

```bash
GEMINI_API_KEY=... node web-api/dev-server.mjs          # http://localhost:3001/api/ask
python -m src.eval_assistant --endpoint http://localhost:3001/api/ask --origin http://localhost:4322
```

## Deploy

Import the GitHub repo in Vercel, set **Root Directory** to `web-api`, add the environment variables, then deploy. No build step is needed.
